# AWS 비용 절감 작업 요약 (팀 브리핑)

> 대상: prod AWS 계정
> 목표: 월 비용 **~17만원 → 10만원 이하**
> 결과: **목표 달성** (핵심 고정비 제거 완료)

---

## 한 줄 요약

인스턴스를 꺼도 계속 나가던 **고정비**(안 쓰는 IP·로드밸런서·모니터링 서버)를 제거하고,
DB와 서버를 최신 세대로 바꾸고, dev 서버를 야간에 자동으로 끄도록 만들어 월 비용을 절반 가까이 줄였습니다.

---

## 무엇을 왜 바꿨나

### 1. 안 쓰는 IPv4 주소 정리
- **문제**: 연결 안 된 유휴 IP가 인스턴스를 꺼놔도 계속 과금됨 (IP 1개당 매달 고정 요금)
- **조치**: 유휴 IP 및 로드밸런서 제거로 딸려 있던 IP들을 반납
- **절감**: 약 **$10/월**

### 2. 로드밸런서(ALB) 제거
- **문제**: Elastic Beanstalk이 붙여둔 ALB가 트래픽과 무관하게 24시간 과금 (월 $15+)
- **조치**: prod 환경을 **로드밸런서 없는 단일 인스턴스(single-instance)** 구조로 전환하고,
  HTTPS(TLS) 종료는 **CloudFront**가 담당하도록 변경
- **절감**: 약 **$15/월**
- **부수 효과**: CloudFront가 앞단에 생겨 인증서 자동 갱신·엣지 캐싱 이점

### 3. 자체 호스팅 모니터링 서버 폐지
- **문제**: 모니터링용 EC2(Grafana + Loki + Prometheus 등)를 **별도로 24시간 운영** →
  서버 비용 + 운영 부담 + 디스크 full로 다운된 이력
- **조치**: 모니터링을 **AWS CloudWatch로 이전**하고, 기존 모니터링 서버는
  **AMI(전체 스냅샷) 백업만 남기고 종료** → 필요 시 언제든 복원 가능
- **절감**: 약 **$8/월** (스냅샷 보관 비용 ~$2.4/월만 잔존)
- 자세한 모니터링 사용법은 → [`monitoring-guide.md`](./monitoring-guide.md)

### 4. RDS(DB) 세대 전환: t3 → t4g (Graviton)
- **문제**: 구세대 인스턴스 클래스는 같은 성능에 더 비쌈
- **조치**: DB 인스턴스를 **Graviton(t4g)** 으로 전환 (엔드포인트 그대로, 앱 변경 0)
- **절감**: 약 **$2.5/월** (동일 성능, 더 저렴)

### 5. dev 서버 야간 자동 종료 (12시간 스케줄링)
- **문제**: 개발 서버가 아무도 안 쓰는 밤에도 24시간 켜져 있음
- **조치**: **EventBridge Scheduler**로 매일 **낮 12시 자동 시작 / 밤 12시 자동 종료** (하루 12시간만 가동)
  - 재시작 후 앱이 자동으로 다시 뜨도록 컨테이너 재시작 정책도 정비
- **절감**: 약 **$7.5/월** (compute 절반)

## Before / After

| 항목 | Before | After |
|------|--------|-------|
| 안 쓰는 IPv4 | 유휴 IP 과금 | 정리 완료 |
| prod 트래픽 처리 | ALB(24시간 과금) | 단일 인스턴스 + CloudFront |
| 모니터링 | 자체 EC2 상시 운영 | CloudWatch (서버 종료, AMI 백업) |
| DB | RDS t3 | RDS t4g (Graviton) |
| dev 서버 | 24시간 상시 | 하루 12시간 (야간 자동 종료) |

### 절감 합계 (월, 대략)

| 작업 | 절감 |
|------|------|
| IPv4 정리 | ~$10 |
| ALB 제거 | ~$15 |
| 모니터링 서버 폐지 | ~$8 |
| RDS t4g | ~$2.5 |
| dev 12h 스케줄 | ~$7.5 |
| **합계** | **~$43/월 (≈ 5.8만원)** |

> 신규 비용(CloudWatch 로그 ~$4/월, AMI 스냅샷 ~$2.4/월)을 감안해도
> 기존 대비 대폭 절감되어 **월 10만원 이하 목표 달성**.

## 개발자가 알아야 할 변경점

- **prod 도메인 앞단이 CloudFront**로 바뀌었습니다 (HTTPS 종료 지점). 기능 동작은 동일합니다.
- **prod EB 환경이 단일 인스턴스**입니다 (로드밸런서 없음). 오토스케일이 필요해지면 재검토 대상입니다.
- **로그·지표는 이제 CloudWatch에서** 봅니다. 기존 Grafana/Prometheus 주소는 더 이상 사용하지 않습니다.
  → [`monitoring-guide.md`](./monitoring-guide.md)
- **dev 서버는 밤 12시 ~ 낮 12시 사이에는 꺼져 있습니다.** 그 시간대에 접속이 안 되면 정상입니다.
  급하면 EC2 콘솔에서 수동 start 하거나 스케줄을 잠시 끄면 됩니다.
- **에러 트래킹은 기존 Sentry 그대로** 유지됩니다.
